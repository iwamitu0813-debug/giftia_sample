# 実装メモ：お母さんへの誕生日タブ（FR-01〜05）

発表で「何を作ったか・なぜそう作ったか」を説明するためのメモです。要件定義書（1121更新）と対応しています。

## 1. 何を作ったか

Giftia の検索画面に、3つ目のタブ「お母さんへの誕生日」を足しました。今ある「いまの検索」「取引先へのお礼」はそのままです。

1. 3つの質問に答える（3問とも任意）
   - Q1 お母さんが最近、困っていること（選択・複数可）
   - Q2 お母さんが「便利そう」「いいね」と言っていた物（自由入力）
   - Q3 去年贈った物と、その結果
2. 合う商品が5つ、「使ってもらえそうな理由」つきで出る

ケースの必須処理（Exhibit 5）との対応：

| 必須処理 | どこでやっているか |
| --- | --- |
| ユーザーの入力を受ける | 画面 MotherForm.tsx の3つの質問 |
| 商品DBから複数の候補を取得する | backend/recommend.py：探す言葉を商品名・説明書きに含む商品を集める |
| チームのロジックで順位付けする | backend/recommend.py：直近1年の販売数の多い順、足りなければ誕生日ランキングで埋める |
| 結果を返す | /api/recommend が5件と理由を返し、RecommendCard.tsx が表示する |

## 2. 全体の流れ（レストランのたとえ）

| 役割 | ファイル | たとえ |
| --- | --- | --- |
| 画面 | giftia-frontend/app/MotherForm.tsx、RecommendCard.tsx | ホール（お客さんが注文するところ） |
| 窓口 | backend/main.py の /api/concerns・/api/recommend | 注文を受ける窓口 |
| 探す・並べる・理由 | backend/recommend.py | 厨房 |
| 言葉の変換 | backend/ai_keywords.py（Claude Haiku 5.5） | 外部の専門家に電話で聞く |
| 困りごと→探す言葉の表 | DB の concern_keywords（backend/sql/concern_keywords.sql） | 倉庫のメニュー表 |

## 3. 工夫したこと（発表で話すポイント）

1. **ランキングを見せる前に、母の手掛かりを聞く**
   Dさんは「何も手掛かりがないから、まず人気を見る」と話し、母の「こういうの便利そうね」を思い出して初めて決められた（Exhibit 2）。だから入口を「母について聞く3つの質問」にした。
2. **「母に合うか」は絞り込み、「安心感」は並べ方で担う**
   まず答えに合う商品に絞り、その中を売れている順に並べる。今のランキング（全商品を売れた順）とはここが違う。
3. **AI に任せるのは「言葉の変換」だけ**
   Q2「旅行に行きたいと言っていた」のような抽象的な言葉や体験を、「トラベル」「持ち運び」のような探す言葉に変えるところだけ AI を使う。候補の選び方・順番・理由はルールで決めるので、同じ入力なら同じ結果になり、理由を説明できる。
4. **AI が遅くても、止まらない**
   AI は合計9秒で打ち切り、Q1の答えだけで探す。Q2とQ3の変換は同時に頼む（2回待たない）。画面は5秒で「考え中です」と出す。APIキーがないときも、AI なしで動く。
5. **必ず5件出る**
   合う商品が5件に足りなければ、誕生日向けランキング（product_scenes の scene_tag＝誕生日）で埋め、「人気の商品です」と分かるように出す。質問をとばしたときも、今までどおり人気順で5件出る。
6. **理由は2行で、根拠を見せる**
   1行目：「お母さんの『〇〇』に合う商品です」。2行目：説明書きの中で一致した言葉の周りの文。Dさんの「これなら使ってくれるかな」に、なぜそう言えるかを添える。
7. **去年の失敗を繰り返さない**
   Q3で「あまり使っていない」「サイズや好みが合わなかった」を選ぶと、去年の品物に近い商品を外す。商品の size 列は内容量（例：フェイスタオル×2）で服のサイズではないため、サイズでは外さず、言葉で外している（Exhibit 4）。
8. **探す言葉は表に置く（プログラムに書かない）**
   商品部が言葉を足したいときは、concern_keywords に1行足すだけ。8,000商品すべてにタグを付けなくても、全商品が対象になる（Exhibit 5：全商品への付与は対象外）。
9. **今あるものを壊さない**
   既存の /api/search と2つのタブは変えていない。新しい窓口も GET にして、CORS の設定（GET だけ許可）を変えずに済むようにした。新しいパッケージも足していない（Claude の API は Python 標準の urllib で呼ぶ）。
10. **秘密は .env だけ**
   Claude の APIキーは .env の ANTHROPIC_API_KEY から読む。コードに書かない・GitHub に上げない・画面側に置かない。

## 5. 聞かれそうな質問と答え

- **売れている順なら、今のランキングと同じでは？** → 今のランキングは全商品を売れた順に並べるだけ。今回はまず母の手掛かりで絞り、その中を売れた順に並べている。
- **AI が間違った言葉を返したら？** → AI は言葉を出すだけで、商品を決めるのはルール。合わない言葉なら商品が見つからず、誕生日ランキングで埋まる。返事の形もチェックし、10文字を超える言葉や重複は捨てる。
- **言葉が一致するだけで「母に合う」と言えるの？** → 弱いところ。説明書きの書き方は商品ごとにばらばら（Exhibit 4）。Phase2 で商品部が困りごとタグを付け、レビューの「使った声」を理由に加える。
- **なぜ付箋（タグ）を付けなかったの？** → 試作用の30〜50点でも7〜11時間かかり、最終報告に間に合わない。対応表なら約25行で全商品が対象になる。より確実なタグ付けは Phase2 で並行して進める。

## 6. 動かし方

1. backend の .env に、AI を使う場合は次の1行を足す（各自。値は GitHub に上げない）
   `ANTHROPIC_API_KEY=（自分のキー）`（Claude Console で作る。チャットの月額プランとは別料金で、使った分だけかかる）
2. backend で対応表を作る（1回だけ）：`python setup_concern_keywords.py`
3. backend：`uvicorn main:app --reload`、giftia-frontend：`npm run dev`
4. http://localhost:3000 の「お母さんへの誕生日」タブで、4. のテストを試す

## 7. テストで見つけた課題と対応（発表で話す）

**現象**：班の DB で Q1「料理やお湯を沸かすなど家事が面倒」を試したところ、焼き菓子が「家事が面倒に合う商品」として出た。理由の2行目は「説明書きに『素材の味がまっすぐ伝わる…』とあります」だった。

**原因**：探す言葉「すぐ」が、「まっすぐ」の中の「すぐ」にも一致した。説明書きを言葉の一部一致（LIKE）で探しているため、短い言葉ほど関係のない文に当たりやすい。要件定義書の付録Aに書いたリスク「言葉の一致だけでは説得力が弱い」が、実際に起きた例。

**対応（Phase1）**：
- 「すぐ」を、意味がはっきりした「すぐ沸く」「沸かす」に置き換えた（backend/sql/concern_keywords.sql）。
- 対応表に置いているので、プログラムは変えずに直せた（工夫8の効果）。

**残る課題と、根本の解決（Phase2）**：
- ほかの短い言葉（「軽い」「香り」など）でも、同じことが起こりうる。班の DB で困りごとごとに結果を見て、外れた言葉を直す。
- 根本の解決は、商品部が商品に困りごとタグを付けること（要件定義書 5.4 Phase2）。人が確かめて付けるので、言葉の偶然の一致に頼らなくなる。
- もう一つの案として、AI に「この説明書きは本当にこの困りごとに合うか」を判定させる方法もある。ただし費用と時間がかかるため、効果を測ってから検討する。

**発表での話し方（例）**：
「実際のデータで試したところ、『すぐ』という言葉が『まっすぐ』に反応して、焼き菓子が家事を楽にする商品として出てしまいました。言葉で探す方法の弱点が、テストではっきりしました。Phase1では言葉を見直して対応し、より確実な方法として、商品部による困りごとタグ付けを Phase2 で進めます。」


## 8. 発表前の見直し：Q1 に「その他（自由入力）」を足した（2026/11/22）

**きっかけ**：画面で試したところ、困りごとは5つのチェックだけでは足りないと分かった（例：「膝が痛くて階段がつらそう」はどれにも当てはまらない）。

**変えたこと**
- Q1 のチェックの下に「その他（自由に書けます）」欄を足した。チェックはそのまま残した。
- 自由入力は AI（Claude Haiku 5.5）が「困りごとを楽にする品物の言葉」に変える（例：膝が痛い → 軽い、クッション、サポート）。
- AI は OpenAI から Claude に変えた。いちばん安く速いモデルで、1回0.01円ほど。
- 質問ごとに AI への頼み方を変えた（Q1その他：困りごとを楽にする品物／Q2：体験を楽しむ品物／Q3-1：去年と同じ種類の品物）。
- 3つの自由入力は同時に AI に聞き、合計9秒で打ち切る（待ち時間は増えない）。

**なぜチェックを残したか（工夫）**
- よくある困りごとは、AI がなくても対応表で**確実に・毎回同じ結果**で探せる。
- 拾いきれない困りごとだけを自由入力と AI で補う。**確実さ（ルール）と柔軟さ（AI）の役割分担**。

**AI が使えないときの予備**
- 入力文と5つの困りごとの「2文字の組」の重なりを数え、いちばん近い困りごとの言葉で探す。
  例：「重い荷物を運ぶのが大変そう」→「重い物を持つ・運ぶのが大変」（重い・運ぶ・大変 が重なる）
- 重なりが少なすぎるとき（例：「膝が痛い」）は当て推量をせず、人気の商品で埋める。

**変えたファイル**：backend/ai_keywords.py、backend/recommend.py、backend/main.py、giftia-frontend/app/MotherForm.tsx、giftia-frontend/lib/api.ts、giftia-frontend/app/globals.css


## 9. メンバーの機能（PR #5）とのつなぎ方（2026/11/22）

そのコードを**なるべく変えずに**、お母さんへの誕生日を足した。
